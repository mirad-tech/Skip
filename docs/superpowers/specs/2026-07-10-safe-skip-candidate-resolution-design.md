# 安全跳过候选解析重构设计

## 目标

在不放宽支付、授权、登录、安装、输入等安全边界的前提下，提高开屏页中纯“跳过 / skip”、小文字节点与可点击父容器组合、以及坐标兜底命中嵌套节点时的识别率。

## 范围与约束

- 仅改变无障碍节点识别、动作目标选择、评分和坐标复验；不改变受保护应用清单或用户规则格式。
- 默认规则允许纯“跳过 / skip”仅当：应用进入前台不超过八秒、包名未受保护、候选位于右上、候选边界小、节点链无输入或高风险语义、且存在稳定的可操作路径。
- 普通“关闭 / × / close”仍必须具备广告或开屏语义，不能因本次改动自动放宽。
- 动作节点优先使用 `ACTION_CLICK`；手势只能在重新校验后作为兜底，且不能点击大容器的中心。

## 设计

### 统一候选解析

新增内部候选解析器，将文字/描述/View ID 所在节点、最近的安全可点击祖先、祖先安全语义、节点链边界和稳定身份组合为一个候选。`NodeScanner`、评分、普通点击和坐标命中均使用该结果，避免各路径分别选择目标。

实际动作节点可为候选节点的近层可点击祖先；候选的视觉边界仍用于区域和小尺寸判断。动作节点的边界不能用于手势中心，除非该动作节点本身满足现有小目标限制。

### 评分与放行

将纯“跳过 / skip”的硬拒绝替换为默认规则专用资格判定。所有资格条件满足时，给予明确的受限分数加成；任一条件不满足时保留失败原因，供日志和诊断使用。自定义规则继续按其已有关键词、最低分和安全策略判定，不获得默认规则的自动放宽。

### 坐标兜底

命中坐标不再机械选取最小节点，而是在包含该点的节点链中选择具有可信身份、低风险语义和可点击路径的候选。初次匹配与延迟前复验必须使用同一稳定身份，继续检查锚点、包名、时间窗、页面敏感语义、输入焦点和位置漂移。

## 验收标准

1. 合规的右上小型纯“跳过 / skip”可被默认规则匹配并以动作点击执行。
2. 中部或大尺寸纯跳过、无可点击路径、受保护包、敏感祖先或活动输入状态均被拒绝。
3. 小文字节点嵌在安全可点击父容器中时，可选择父容器执行动作；手势兜底不会按父容器中心盲点按。
4. 无广告/开屏证据的通用“关闭 / × / close”仍不达阈值。
5. 坐标命中装饰子节点、而安全父节点提供身份和点击路径时，初次匹配与复验一致通过；身份、锚点、页面或位置变化时拒绝。
6. 单元测试覆盖所有允许与拒绝分支，并保留既有高风险和坐标安全测试。

## 验证策略

- 先为上述允许和拒绝路径补充失败测试，再实施。
- 运行 JVM 单元测试、现有无障碍仪器测试及静态构建任务。
- 检查日志失败原因仍能区分低分、无动作目标、敏感语义和坐标复验失败。
